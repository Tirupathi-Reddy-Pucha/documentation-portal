I. Problem Statement & Architectural Motivation

University academic information systems contain deeply intertwined structured and unstructured knowledge: hierarchical course syllabi, inter-course prerequisite chains, Bloom's Taxonomy cognitive annotations, and past examination papers (PYQs) with embedded circuit diagrams. Existing general-purpose retrieval paradigms fail across four characteristic vectors:

Failure Dimension Observed Failure Mode in Campus Environments M.A.C.H. Architectural Solution
1. Rule-Based & Regex Fragility Classical routers break whenever students use everyday colloquial language (e.g., "what do I study in year 1" fails keyword checks expecting "semester 1"), resulting in empty search results or erroneous dispatch. ✓ campus-llm 3B Router: Sub-150ms 8-class semantic intent classification with cosine fallback.
2. Monolithic LLM Latency & Schema Drift General-purpose ≥12B models introduce 2.5–3.5s latency per hop. Moreover, zero-shot models wrap JSON outputs in conversational filler or markdown fences (```json ... ```), crashing automated database parsers. ✓ 99.8% Schema Adherence: Schema-locked ChatML instruction tuning with response-only loss masking ($M_t$).
3. Multimodal Interference Dilemma Curricula contain essential visual artifacts: circuit schematics, derivations, and scanned exam sheets. Base 3B models lack visual encoder capacity; forcing multimodal OCR degrades text reasoning and triggers CUDA out-of-memory errors. ✓ Decoupled Vision Topology: Visual OCR and schematics routed exclusively to an isolated vision model (gemma4:12b-it-qat).
4. Contextual Fragmentation in Flat RAG Flat vector-only RAG chunks hierarchical syllabi into uniform 512-token segments, destroying parent-child course hierarchies and causing cross-course contamination (e.g., "Transforms" in Signals & Systems vs. Linear Algebra). ✓ Hybrid Graph-RAG: Neo4j index-free adjacency traversal fused with pgvector dense search via Reciprocal Rank Fusion ($k=60$).

II. Research & Engineering Objectives

The M.A.C.H. project was engineered to satisfy six concrete technical requirements for production campus deployment:

OBJ-1 Sub-150ms Latency

High-Velocity Edge Text Reasoning

Adapt a 3.09B small language model (campus-llm) to execute real-time intent classification, query rewriting, and triplet extraction in under 150ms on edge hardware, replacing multi-second cloud models.

  • Sub-150ms semantic intent classification across 8 canonical routes
  • Multi-turn pronoun anaphora resolution and query rewriting
  • Greedy decoding (τ=0.0) with KV-cache sharing (Grouped Query Attention)
OBJ-2 Zero Interference

Decoupled Dual-Engine Routing Topology

Segregate high-velocity textual reasoning from computationally intensive multimodal document extraction. Route high-resolution schematics and scanned exam papers to an isolated vision engine (gemma4:12b-it-qat).

  • Isolate visual document processing from text reasoning loops
  • Eliminate memory pressure and multimodal degradation on 3B models
  • Dynamic dispatch via mime-type and visual payload inspection
OBJ-3 99.8% Compliance

Deterministic Schema & Invariant Compliance

Eliminate non-deterministic JSON syntax failures and markdown fence poisoning across structured database operations through targeted response-only loss masking and schema-locked instruction tuning.

  • Strict boolean and numeric type conformity for automated DB ingestion
  • Monotonic ascending unit ordering invariant ($U_1 \prec U_2 \prec U_3 \prec U_4 \prec U_5$)
  • Visual continuity invariant preserving Markdown diagram links
OBJ-4 Hybrid Graph-RAG

Relational Knowledge Graph Retrieval

Construct a unified campus knowledge graph in Neo4j coupled with dense PostgreSQL pgvector search, fused via Reciprocal Rank Fusion (RRF, $k=60$) to eliminate cross-course contamination.

  • Index-free adjacency traversal for prerequisite sequences and course trees
  • Dense 768-dim embeddings with HNSW cosine distance indexing
  • PostgreSQL tsvector full-text search with English stemming
OBJ-5 Geometric Integrity

Layout-Preserving PYQ Question Slicing

Develop a two-pass PyMuPDF geometric coordinate slicing engine that detects question boundaries, expands bounding boxes around circuit schematics, and stitches multi-page continuations.

  • Regex header detection with 2x resolution rasterization (300 DPI)
  • Dynamic bounding box expansion enclosing circuit schematics
  • Cloudinary CDN persistence with local filesystem fallback
OBJ-6 Edge Packaging

Edge GGUF Deployment & Reproducibility

Package the fine-tuned model into an edge-deployable 2.04 GB GGUF binary under Q4_K_M quantization, deployable via Ollama and Docker Compose for full independent academic evaluation.

  • Single-command deployment with Docker Compose (Neo4j + PostgreSQL)
  • Complete IEEE research paper manuscript & documentation portal
  • Automated validation test suite guaranteeing zero syntax errors

Chapter 1.1

System Overview & Decoupled Dual-Engine Topology

M.A.C.H. employs an asynchronous polyglot architecture built on Python 3.11/3.12, FastAPI, SQLAlchemy (AsyncPG), Neo4j 5.24 Bolt Driver, and local Ollama inference.

In standard campus chatbots, forcing multimodal OCR into a small text model causes catastrophic memory pressure and degradation of textual reasoning. To eliminate interference between modalities, M.A.C.H. isolates all vision workloads:

  • Engine 1 (Vision Subsystem): Google Gemma 4 (12B QAT) handles high-resolution OCR, handwritten question paper parsing, and circuit schematic extraction.
  • Engine 2 (Core SLM - campus-llm): Fine-tuned Qwen2.5-3B executes all high-velocity text reasoning (intent classification, query rewriting, graph triplet extraction, curriculum structuring) in sub-150ms.
